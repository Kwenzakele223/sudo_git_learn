# Product Backlog

## Overview

The Product Backlog is a prioritised list of all the work required to develop the **Sudo Git Learn** application. It represents the project's requirements and serves as the primary source of work for the development team. Backlog items are prioritised based on business value and may be refined throughout the project.

| ID | Feature | Description | Priority | Status |
|----|---------|-------------|----------|--------|

| PB-001 | Project Setup | Set up the project repository, folder structure, documentation, and development environment. | High | Done |


| PB-002 | User Interface | Design and develop the application's user interface. | High | Not Started |


| PB-003 | Navigation | Implement navigation between pages, lessons, and learning modules. | High | Not Started |


| PB-004 | Linux sudo Module | Develop interactive lessons for Linux `sudo` commands. | High | Not Started |


| PB-005 | Git Module | Develop interactive lessons covering Git fundamentals. | High | Not Started |


| PB-006 | Terminal Simulator | Create a browser-based terminal simulation for executing commands. | High | Not Started |


| PB-007 | Command Validation | Validate user input and provide appropriate feedback. | High | Not Started |


| PB-008 | Lesson Management | Manage lesson progression, completion, and unlocking of new lessons. | Medium | Not Started |


| PB-009 | Progress Tracking | Track and save learner progress. | Medium | Not Started |


| PB-010 | Learning Resources | Provide hints, explanations, and a command cheat sheet. | Medium | Not Started |


| PB-011 | Responsive Design | Ensure the application works on desktop, tablet, and mobile devices. | Medium | Not Started |


| PB-012 | Testing | Perform unit, integration, acceptance, and manual testing. | High | Not Started |


| PB-013 | Deployment | Deploy the application and prepare the production release. | Medium | Not Started |

---

## Priority Levels

| Priority | Description |
|----------|-------------|
| High | Essential features required for the application to function. |

| Medium | Important features that improve the learning experience. |

| Low | Future enhancements that can be implemented after the core functionality is complete. |

---

## Backlog Maintenance

The Product Backlog is a living document. It will be reviewed and updated throughout the project to:

- Add new requirements.
- Refine existing backlog items.
- Re-prioritise work based on project needs.
- Remove obsolete items.
- Prepare work for upcoming sprints.
